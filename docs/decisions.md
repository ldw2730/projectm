# 결정 기록

중요한 결정을 최신순으로 남긴다. 나중에 "왜 이렇게 했지?"에 답할 수 있게 하는 게 목적이다.

## 2026-11-25: 1차 플랫폼은 웹
- **결정**: 1차는 웹으로 만든다. 모바일 웹, PWA, 데스크톱 지원 범위 같은 세부 형태는 아직 정하지 않았다.
- **이유**: 사용자 판단("웹이 낫겠다"). idea-critic 검토도 1차를 모바일 웹/PWA로 권장했다. 공유 링크가 원래 웹이라 코드베이스를 하나로 유지할 수 있고, 스토어 심사와 Google Play 위치 권한 선언 문제가 생기지 않는다.
- **검토한 대안**: 초안의 모바일 앱 본체(Flutter/React Native) + 공유만 웹
- **따라오는 과제**: iOS 웹에서 사진 위치 정보(EXIF)가 빠지는 문제를 시제품으로 확인해야 한다. AR 단계에서 정밀 앵커링이 필요해지면 네이티브 앱 전환을 다시 검토한다.
- **관련 문서**: docs/ideas/ar-place-story.md

## 2026-11-25: 대상 사용자는 좁히지 않고 포괄
- **결정**: 여행자나 일상 탐방자 중 하나로 좁히지 않는다. 사용자 유형은 서비스가 나누지 않고, 각 사용자가 카테고리와 해시태그로 자유롭게 구분한다.
- **이유**: 사용자 판단
- **검토한 대안**: idea-critic이 제안한 변형안 A(다녀와서 넘기는 "한 줄 가이드", 여행자 대상)와 변형안 B(동네 단골 기록장, 일상 탐방자 대상)
- **따라오는 과제**: 대상이 넓어지면서 게이트 1 지표(초안: 2주차 재방문 기록)를 다시 정해야 한다.
- **관련 문서**: docs/ideas/ar-place-story.md
